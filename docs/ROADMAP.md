## 0. 审计结论（2026-10-21，量化能力审计）

按「可信度」优先级列出硬问题。状态：`待修` / `修复中` / `已修` / `M1.5`（明确后移且有降级保护）。

| # | 问题 | 影响 | M1 处置 |
|---|------|------|---------|
| 1 | 实盘 `time_stop` 永不触发：`Position` 无 `entry_day`，`_held_days` 恒 0 | 时间止损形同虚设 | 持仓元数据落库（M1-A） |
| 2 | 实盘 `trailing_stop` 峰值口径错误：`peak_price` 恒 0，只剩成本价/当日高点 | 移动止盈过晚/过频 | 峰值落库 + 盘中更新（M1-A） |
| 3 | 回测 `once: true` 是「全程一次」，实盘是「每天一次」 | 回测低估/高估交易频率 | 回测按日语义（M1-B） |
| 4 | 回测按 T+1 收盘成交，文档/实盘是 T+1 开盘；日线路径未冻结当日买入、未过组合仓位上限 | 回测与实盘不可对照 | T+1 开盘 + 冻结 + 风控接入（M1-B） |
| 5 | 引擎/条件单不调用组合回撤/日亏熔断；峰值只存内存，重启归零 | 熔断只在 CLI/AI 生效 | 风控状态落库 + 盘中熔断（M1-C） |
| 6 | 风控计价把当前标的价格填给所有持仓 | 总仓位/单票上限失真 | 按标的最新价计价（M1-C） |
| 7 | 引擎未排除当日未收盘日线 | 盘中可能出现 T+0/未来函数 | 排除当日未收盘日线（M1-C） |
| 8 | 无分红/送转/拆股处理；前复权只保证信号连续 | NAV/现金/股数在除权日静默失真 | 检测 + 审计 + 人工调整入口（M1）；自动调整 M1.5 |
| 9 | 交易时段把节假日/午休算作盘中（实测 10-01 10:00 与午休 12:00 均 True） | 非交易时段可能成交 | 时段收紧 + 报价新鲜度（M1-D） |
| 10 | 规则级 `enabled: false` 不生效；`engine.universe` 未使用 | 配置语义失效 | 语义落地（M1-E） |
| 11 | 规则/条件/AI 预算各自计数 | 单日总量可被叠加绕过 | 引擎+条件单共用日预算（M1-E）；AI 保留单轮上限并文档说明 |
| 12 | 回测默认滑点 0，实盘 0.01；无涨跌停/停牌约束 | 回测偏乐观 | 口径对齐（M1-B） |
| 13 | 条件单日上限按 `created_at` 统计 | 跨日挂单可绕开上限 | 按成交日统计（M1-E） |
| 14 | 科创板 688 最低买入 200 股未建模 | 可造出实盘不接受的单 | 最低 200 股校验（M1-E） |

半成品/名不副实项（不阻塞 M1，登记在案）：`Portfolio` 与账户快照能力重叠、部分策略方案仅参数化、面板「引擎」页只读展示、`optimize` 网格样本极小时结论仅供参考。

## 1. M1 — 正确性与口径统一（v0.6.0）

### 验收标准（全部满足才可开 `engine.enabled`）

- [x] 上表 1–14 全部修复，或明确降级为 M1.5 且已有 fail-closed 保护。
- [x] 新增回归测试覆盖每一项修复；**回测-实盘对照测试**锁定：
      同一规则、同一日线序列、同一风控参数下，「是否成交 / 成交日 / 成交价口径 / T+1 是否可卖」一致。
      （`tests/test_m1_correctness.py::test_backtest_vs_simulated_live_tick_parity`）
- [ ] 本地与 Pi 双端 `python -m pytest -q` 全绿。（本地 170 项全绿；Pi 待部署后跑）
- [ ] v0.6.0 发版、Pi 部署、母项目确认按 tag 取用。
- [ ] 本文件勾选完成，`engine.enabled` 才允许从 `false` 改为 `true`（改之前先在 Pi 上 `--dry-run` 观察一个交易日）。

### M1-A 持仓元数据（实盘止损可信）

- [x] `Position` 增加 `entry_day`、`peak_price` 字段；`positions` 表迁移（旧库 `ALTER TABLE`，不重建）。
- [x] 旧持仓迁移回填：`entry_day` 取最早买入成交日；`peak_price` 至少不低于成本价。
- [x] 买入：新仓写 `entry_day=成交日`、`peak_price=成交价`；加仓保留首仓日、峰值取 max。
- [x] 盘中每轮更新持仓峰值（实时价/当日高点/建仓以来日线高点），**落库**，重启不丢。
- [x] `time_stop`：`_held_days` 用「建仓日之后**已收盘**的交易日数」计数（与回测 `trading_days_held` 同口径）。
- [x] `trailing_stop`：峰值 = max(落库峰值, 成本价, 当日高点, 建仓以来日线高点)。
- [x] 单测：新仓/加仓/部分卖出/清仓的元数据流转；重启后再评估 `time_stop` 能触发。

### M1-B 回测-实盘口径统一

- [x] 信号 T 日收盘判定，最早 **T+1 开盘**成交（成交价 = T+1 开盘价 ± 滑点；无开盘价不成交）。
- [x] 日线路径也执行 **T+1 冻结**：当日买入的部分当日不可卖（与盘中一致）。
- [x] `once` 语义改为**按交易日**：同一规则每天最多触发一次，回测与 `EngineState.fired_rules` 一致。
- [x] 回测接入组合风控（`max_single_order_value` / `max_position_pct` / `max_total_position_pct`），
      与 CLI/引擎共用同一组 `risk` 参数；被风控拒的单进 `skipped`。
- [x] 回测默认滑点与 `config.yaml` 一致（固定 0.01 元，可覆盖）；CLI 显式传参。
- [x] 保守撮合约束：开盘一字涨停不买入、开盘一字跌停不卖出；停牌（当日无 K 线）不成交且在 `skipped` 说明。
- [x] `grid_search` / `walk_forward` 透传 `risk` 与滑点参数（研究结论与生产口径一致）。
- [x] 新增对照测试：同一序列分别跑回测与「模拟实盘 tick」，关键结论一致。

### M1-C 账户级风控与计价

- [x] `RiskManager` 峰值与**当日亏损基线**落库（`paper_account.db` 新表 `risk_state`），重启后熔断不被绕过。
- [x] 引擎每轮：先算全账户 NAV（按各标的最新价）→ 更新峰值 → 检查组合回撤与当日亏损；触发即本轮零下单。
- [x] 条件单每轮同样先过账户级熔断；触发熔断时条件单**保持 armed**（不误标 rejected）。
- [x] 引擎/条件单风控计价：所有持仓按各自最新价（实时优先、缺价回退最近收盘），不再用当前标的价格填全场。
- [x] 引擎日线规则上下文**排除当日未收盘日线**（只用到最近已收盘交易日）。
- [x] AI agent 的日亏检查改用同一份落库基线（方案阈值仍可覆盖），账户级口径一致。
- [x] 单测：熔断落库重启后仍拦截；多持仓不同价格时总仓位计算正确；当日日线被排除。

### M1-D 交易时段与报价新鲜度

- [x] `is_trading_session` 只认连续竞价 **9:30–11:30 / 13:00–15:00**（周一至周五）。
- [x] 解析腾讯行情时间戳；**日期不是当天**或**距当前超过新鲜度窗口**（默认 180 秒）的报价丢弃。
- [x] 午休、节假日、收盘后、开盘前：`get_quotes` 返回空 → 引擎/条件单零成交（测试锁定）。
- [x] `config.yaml holidays` 保持可用（T+1 解冻跳节假日）；自动交易日历同步列入 M1.5。
- [x] 单测：10-01 节假日、午休 12:00、15:01、09:00、周末均不交易；新鲜报价可通过。

### M1-E 其他硬问题

- [x] 规则级 `enabled: false` 真正生效（引擎跳过、回测不参与、面板/CLI 显示禁用）。
- [x] `engine.universe` 语义落地：`list`=只用规则点名的标的；`auto`=允许规则缺省标的时取本地股票池（上限保护）。
- [x] 引擎与条件单**共用同一个日内订单预算**（同一账户同一天总量不被叠加绕过）。
- [x] 条件单日上限按**成交日**统计，不按创建日。
- [x] 科创板 688 买入最低 200 股校验（fail-closed，拒单落库）。
- [x] 除权除息（降级为 M1.5，本期先有保护）：
  - [x] 同步数据时检测「历史收盘被回溯调整」（前复权因子变化）→ 记 `op_log` 告警，不静默。
  - [x] `PaperBroker.apply_corporate_action(symbol, ex_date, cash_per_share, share_ratio)`：现金分红入账、送转股调整股数与成本，全程可审计。
  - [x] CLI `corporate apply` 人工调整入口 + 文档说明口径（分红税、送股上市日简化为 M1.5 细化）。
  - [x] 文档明确：M1 之前，除权除息日 NAV 可能失真且**不会自动修复**，必须人工核对。

> **除权除息 M1 口径（务必人工核对）**：前复权数据会在除权后重算历史收盘，
> 同步时检测到差异会写 `op_log`（`data:revision`），但**不会自动改账本**。
> 除权日 NAV/股数可能失真，必须人工确认后用
> `python -m paper_trading.cli corporate apply --symbol ... --ex-date ... [--cash-per-share ...] [--share-ratio ...]`
> 调整；自动检测与分红税细化在 M1.5。

### M1.5 — 除权除息自动化（M1 之后、M2 之前）

- [ ] 行情数据质量守卫：缺口、重复、异常涨跌幅、长期停牌标记；同步失败可见（不静默）。

- [ ] 参数研究流程固化：样本内选择 → 样本外检验 → 前向模拟；禁止把网格第一名直接写生产。

## 3. M3 — 策略与组合

- [ ] 多策略并行与资金分配（方案层），组合层风控统一入口。
- [ ] 策略健康度：滚动超额、回撤、换手、费用拖累；策略失效自动降级为观察。
- [ ] AI 选股与规则执行的分工审计：AI 提名 → 程序校验 → 规则择时，每步可回放。
- [ ] 报告：日/周报（持仓、成交、归因、风控事件），CLI 可导出。

## 4. M4 — 可运维与可审计

- [ ] 账户与风控状态备份/恢复演练；`paper_account.db` 迁移工具与版本化。
- [ ] 任务监控：cron/守护进程心跳、报价源健康、熔断事件通知。
- [ ] 审计报告：任意一天可回答「为什么买/为什么没买/为什么卖」。
